# 大模型协作记录

本文件记录本作品开发过程中使用通用大模型（对话式编码助手）的方式、提示词与纠错过程，
对应竞赛指南 3.3.5.3 中「大模型协作记录」一项。所有内容来自实际交互，按时间与用途归类；
下列提示词经过脱敏与合并同类项，保留了当时的约束条件与判断依据。

---

## 一、协作方式

| 任务类型 | 承担部分 | 不承担部分 |
|---|---|---|
| 文档与图表 | 结构化写作、图表脚本（Pillow 绘制框图）、排版与分页 | 指标数值、口径判断 |
| 代码与脚本 | 权重导出脚本、校验脚本、HLS 测试台的框架 | 算法结构与硬件微架构的决策 |
| 排查与复现 | 从报错/日志定位方向、给出排查顺序 | 最终判断（都需回到板上或报告验证） |

**贯穿全程的三条约束**（每次对话都重新声明）：

1. 文档中出现的每一个数字必须能追溯到实测日志或工具报告，模型不得自行推算或补全；
2. 同一指标只能有一种口径，口径变化必须显式声明（例如加速比是「单层」还是「整网」）；
3. 涉及学校、姓名等身份信息一律不出现。

## 二、典型提示词与产出

### 2.1 把日志与源码整理成技术文档

```
约束：所有数字必须与 1/run copy 2.txt 和源码一致；不要出现学校名称；
结构按模板的第一至第五部分；图表用脚本生成，不贴截图。
输入：串口日志、HLS/PS 源码目录、Vivado 报告截图上的数值。
输出：可直接排版的 .docx，图由 Pillow 脚本生成。
```

模型先给出章节骨架，再逐节生成内容。骨架阶段就要求它**列出每一节将引用的数据及其出处**，
这一条显著减少了后文出现「漂亮但无出处」的数字。

### 2.2 生成框图

```
把这个系统的数据流画成框图：作业场景→相机→PL 加速器→PS→STM32→云台/激光。
要求：箭头端点落在方框边上，不要悬空；标签不要盖住箭头；同类模块同色。
用 Python + Pillow 生成，不要用截图拼。
```

第一版存在三类问题，都是人工看图后指出的（见第三节）。

### 2.3 定点误差与资源数据的校验

```
这是导出脚本生成的权重清单和板上 dump 的单层输出（int16，缩放 512），
参考值是 PC 端 float32 输出。给出误差统计，并判断是整体缩放问题还是个别通道问题。
```

对应 `skill/03-fixed-point-checker/`，后来把这段提示词固化成可直接运行的脚本，
不再每次让模型现算 —— 这是「技能包」的第一个来源。

## 三、自我纠错轨迹（三次典型返工）

### 3.1 加速比口径被写宽

- **模型初稿**：「识别这一帧比 CPU 快 106 倍」。
- **问题**：106× 只对应第 1 层卷积（同层 PL 8.26 ms vs ARM 874 ms），整网是 429 ms/帧，
  用单层倍数描述整帧会让结论站不住。
- **修正**：全文统一为「第 1 层卷积 106×；整网 429 ms/帧」两句并列；
  并明确 90.8× 是「整网与第 1 层的计算量之比」，不是一个加速比。
- **沉淀**：在文档撰写提示词里固定一条「指标必须带适用范围」，写进 `skill/01` 的验收项。

### 3.2 框图连线画错

- **模型初稿**：箭头终点落在面板边框而非目标方框；UART 方向画反；反馈箭头退化成一段短线。
- **发现方式**：人工对照系统架构逐条看连线，指出「这两个图线都没画好」。
- **修正**：重写连线函数，规定箭头必须落在方框边缘坐标上；方向按「谁发起」定；
  反馈路径改为整行下方走线，标签盖在线上（加白底遮罩）。
- **沉淀**：把「端点必须在边上、标签不得遮挡箭头」写成生成脚本里的硬约束，
  并作为后续所有框图的检查项。

### 3.3 图表占用整页

- **现象**：图 1-1 单独占一页，前页只剩几行正文。
- **分析**：正文约 4.4 页，第二部分强制另起一页，导致第一部分的末尾只有一行正文 + 整图。
- **修正**：精简第一部分的重复表述、缩小图内标题、调整行距与段间距，
  让图排在第 4 页底部，全篇从 23 页降到 21 页。
- **沉淀**：生成文档后必须逐页渲染检查（转 PDF 后测量每页文字底边位置），
  而不是只看页数。

## 四、边界与教训

1. **模型擅长结构与表达，不擅长判断「什么算实测」**：凡是数字，必须由人给出出处，
   模型只负责组织。它天然会补齐看起来合理的数值，因此每次输出后都要逐项核对出处，
   对不上的一律删掉而不是保留待查。
2. **提示词里要写失效条件**：只说「画框图」得到的图往往细节正确、层次混乱；
   加上「同类模块同色、箭头落在边上、不要交叉」之后质量稳定。
3. **纠错要沉淀成规则**：三次返工最后都变成了脚本约束或文档检查项，
   而不是只改这一次的产物 —— 这也是 `skill/` 目录存在的意义。
4. **模型不能替代上板验证**：所有结论在写入报告前都回到板子上复测过一遍。
