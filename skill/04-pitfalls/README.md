# 04 · Zynq 软硬件联调踩坑清单

条目按「踩到的频率」排列。每条给出：症状 → 触发条件 → 排查步骤 → 修复。
排查步骤是**有先后顺序的**，按顺序做能最快把范围缩到一个小模块。

---

## 1. 定点位宽与缩放因子对不上

**症状**：输出整体偏大/偏小一个固定倍数；或某些层突然贴限饱和，检测框整体偏移。

**触发条件**：改了 `ap_fixed<W,I>` 的 `I`，但没同步改软件端的 `SCALE`；
或者 BN 折叠后权重量级变了，重新导出时仍用旧缩放。

**排查**
1. 取单层，喂一个已知输入（如全 1），手算期望输出；
2. 用 `skill/03` 的 `fx_compare.py --per-channel` 比对，看是整体倍数还是个别通道；
3. 整体倍数 → 缩放因子问题；个别通道 → 该通道累加器位宽问题；
4. 饱和计数 > 0 → 位宽不够，先加整数位再谈精度。

**修复**：把 `SCALE` 写成源码里唯一的宏，导出脚本与 PS 侧共用同一份定义，不要两处手写。

---

## 2. HLS IP 的 AXI 端口与 PS 侧不一致

**症状**：加速器一启动就挂死，或读回全 0；AXI 总线上没有事务。

**触发条件**：HLS 里 `m_axi` 的数据位宽、`depth` 或 `offset` 选项改了，
但 Vivado BD 里还是旧 IP，或 PS 侧按旧地址访问。

**排查**
1. 在 Address Editor 里确认每个 `m_axi` 口都分配了地址，且高地址位正确；
2. 用 ILA 抓 `AWVALID/WVALID`，看有没有握手；
3. 检查 PS 侧传入的指针是否是物理地址（裸机下直接传虚拟地址可能正好等于物理地址，
   一旦开了 MMU/Cache 就错）。

**修复**：HLS 重新导出 IP 后，务必在 BD 里「升级 IP」并重新校验地址映射；
地址表以 `xparameters.h` 为准，不要手抄。

---

## 3. 分块之后「算得快、等得久」

**症状**：加速器空闲率高，DDR 带宽被打满，整网延迟远大于加速器自身周期数。

**触发条件**：tile 分得太小，每块都要重新读权重与重叠的输入行；或没有乒乓缓冲，
加载和计算串行。

**排查**
1. 粗算每层访存量 = tile 数 × 每 tile 读入字节，与 DDR 带宽比对；
2. 看加速器 IP 的 idle 信号占比；
3. 若访存时间 ≈ 计算时间，说明没有重叠。

**修复**：输入/权重/输出各设一组乒乓缓冲，把加载、计算、写回做成三级流水；
必要时把权重常驻片上（BRAM），只让输入输出走 DDR。

---

## 4. 多路 AXI 主口共享带宽

**症状**：接口逻辑都对，但吞吐在某个数值上卡住，且与数据量无关。

**触发条件**：多个 `m_axi` 口映射到同一 HP 口，或 VDMA 与加速器抢同一个口。

**排查**：在 BD 里看每个 HP 口上挂了几个主设备；用 AXI Performance Monitor
或 ILA 看每个口的实际带宽。

**修复**：把读、写、权重分开到不同 HP 口；给实时性要求高的口单独分配。

---

## 5. DVP 摄像头不出图

**症状**：HDMI 全黑或花屏；`vsync/href` 有翻转但数据不对。

**触发条件**：XDC 里时钟/数据引脚写错；PCLK 极性或采样沿不对；
没有做输入延迟（IDELAY）校准。

**排查**
1. 先用 ILA 只看 `pclk / vsync / href / data`，确认帧结构正常；
2. 抓一行数据，看颜色顺序（RGB565 的字节序很容易反）；
3. 若是花屏成斜纹，多半是采样沿错误或 PCLK 域未约束。

**修复**：按原理图核对引脚；`create_clock` 给 PCLK 加约束，
跨时钟域用异步 FIFO，不要在 PL 里直接跨域比较。

---

## 6. 串口帧与看门狗打架

**症状**：下位机偶尔丢帧，或激光在目标消失后仍然亮着。

**触发条件**：上位机每帧发一次坐标，下位机超时时间短于最长帧间隔；
或者帧解析没有校验和，噪声被当成有效帧。

**排查**
1. 记录串口时间戳，算最大帧间隔（本作品实测约 459 ms/拍）；
2. 超时阈值取最大间隔的 2 倍以上；
3. 加帧头 + 校验，解析失败直接丢弃，不要「尽最大努力修复」。

**修复**：超时保护只做最后一道兜底，正常路径要靠帧本身的有效性；
激光类执行器还要再加一个「单次最长照射时间」硬上限，与通信状态无关。

---

## 7. 板上读不到权重

**症状**：程序跑通但检测结果全空或全是乱框。

**触发条件**：权重文件没拷到 SD 卡根目录、文件名大小写不符、
或导出时用 float32 而板上按 int16 读。

**排查**
1. 串口打印文件打开结果与文件长度，与 `export_weights.py` 输出的大小核对；
2. 读第一层权重的前 8 个值，与 PC 端导出的前 8 个值比对；
3. 长度对但数值对不上 → 类型/字节序问题；长度都不对 → 路径问题。

**修复**：在导出脚本里生成一份清单（文件名、元素数、dtype、缩放因子），
板上启动时按清单逐个校验并打印，缺一个就直接报错退出，不要静默继续。

---

## 使用方式

遇到问题时先按症状在表里定位，再按排查步骤的顺序执行 —— 顺序本身是经验，
跳步会绕远。修完一条后，把「现象 → 根因 → 修法」补回本文件，清单才会越长越有用。

## 失效条件

- 器件不是 Zynq-7000 系列（第 3、4 条针对 AXI HP 结构，其他平台对应概念不同）；
- 使用 PYNQ / Linux 而非裸机（第 2、7 条涉及 MMU 与文件系统的部分需改写）；
- 摄像头不是 DVP 并口（第 5 条针对并行接口，MIPI/LVDS 需另写）。
