# skill/ — 与题目无关的可复用技能包

本目录是把开发过程中与大模型协作的经验**显式提炼**出来的产物，不是本作品的使用说明。
判据只有一条：**一支没做过这个项目的队伍，拿到这里的一个目录，能不能直接用在自己的题目上。**

按竞赛指南 3.3.5.2 的要求，每一项都写明：适用范围、使用方法、失效条件、已验证效果，
以及它是从哪一次失败或观察中总结出来的。

| 技能 | 类型 | 解决的问题 | 依赖 |
|---|---|---|---|
| [`01-hw-sw-partition/`](01-hw-sw-partition/README.md) | 提示词工作流 | 拿到一个算法，怎么在给定器件上切出软硬件边界、定并行度 | 无 |
| [`02-report-triage/`](02-report-triage/README.md) | 提示词工作流 | 综合/实现报告出来后，先看哪一行、按什么顺序改 | 无 |
| [`03-fixed-point-checker/`](03-fixed-point-checker/README.md) | 校验脚本 | 定点输出相对浮点参考到底差多少、差在哪一层 | Python + numpy |
| [`04-pitfalls/`](04-pitfalls/README.md) | 踩坑清单 | Zynq 软硬件联调时反复踩的 7 个坑及其定位步骤 | 无 |

## 通用性说明

- `01` / `02` 是纯提示词模板，不依赖 AMD 器件型号，换成 Intel/Altera 或纯 RTL 流程同样成立；
- `03` 只要求两边输出是「同样元素数、同样布局的裸二进制」，与是否是 CNN 无关，
  任何定点 DSP 链（滤波、FFT、矩阵乘）都能用；
- `04` 的前三条是 Zynq-7000 通用问题，与本题目的卷积阵列无关。

## 使用方式

每个子目录下的 `README.md` 是唯一入口，结构固定：适用范围 → 输入 → 步骤 → 验收 → 失效条件。
脚本类技能附带可运行的 `.py` 与一段自测数据，直接 `python xxx.py --selftest` 即可验证环境。

## 沉淀来源

本目录的内容来自开发过程中真实发生的三次返工，报告第四部分有对应记述：

1. **面积与并行的取舍**：要把 DSP 用满才能达到 429 ms/帧的整网速度，但并行度越高，
   布线与时序越难收敛 —— 见 `01` 的「并行度定标」与 `02` 的「DSP 撞满之后看谁」；
2. **分块之后的带宽塌陷**：改成 13×13 分块后出现「算得快、等得久」，DDR 访问把流水线切碎，
   最后靠输入/权重/输出三组乒乓缓冲才把加载、计算、写回重叠起来 —— 见 `02` 的「带宽优先于面积」；
3. **定点与浮点的偏差**：Q7.9 量化后需要逐层确认误差没有在某处被放大 —— 见 `03` 的分层比对做法。

每条技能里都保留当时的现象描述，方便判断「我遇到的到底是不是同一个问题」。
