# 03 · 定点误差比对脚本（fx_compare.py）

## 适用范围

任何「浮点参考实现 + 定点硬件实现」需要比对输出的场合：CNN 加速器、定点 FIR/FFT、
矩阵乘、图像处理流水线。只要求两边输出是**同样元素数、同样布局的裸二进制**，
与是否 Zynq、是否 CNN 无关。

不适用于：动态长度输出（需先对齐长度）、带内部状态的流式输出（需先确定稳态区间）。

## 输入

| 文件 | 格式 | 说明 |
|---|---|---|
| 参考输出 | float32 / float64 裸二进制 | PC 端浮点实现，或 PyTorch/NumPy 的参考结果 |
| 被测输出 | 任意整数类型裸二进制 | 板上 dump 出来的结果；`--scale` 指定缩放因子 |

需要用 `--shape` 告诉它布局，否则最差位置只能给出一维下标。
若形状是 `(通道, 高, 宽)`，加 `--per-channel` 可直接定位到哪一层 / 哪个通道出问题。

## 使用方法

```bash
# 1. 先自测环境（不需要任何数据）
python fx_compare.py --selftest

# 2. 最基本的比对：Q7.9（缩放 512）
python fx_compare.py ref_f32.bin dut_i16.bin --dut-dtype int16 --scale 512

# 3. 带形状与阈值：误差超过 0.05 就返回非零退出码，可接进 CI
python fx_compare.py ref.bin dut.bin --scale 512 \
       --shape 32,13,13 --per-channel --tol 0.05
```

输出包含：总体最大/RMS/相对 RMS/99 分位误差、饱和样本数、逐通道误差、最差 N 个位置。

## 判据怎么定

| 场景 | 合理的阈值 |
|---|---|
| 定点量化的理论下限 | 半个 LSB，即 `0.5 / scale` |
| 中间层（会继续累加） | 1~2 个 LSB，误差允许被下一层放大 |
| 网络最终输出（检测框坐标） | 按任务定：本作品用 0.05（约 25 个 LSB）仍不影响检测框 |

**先跑一次不带 `--tol` 的**，看清误差分布再定阈值，不要拍脑袋写数。

## 验收

- `--selftest` 跑通，且报告的最大误差等于半个 LSB；
- 对已知正确的实现，最大误差不超过 1 个 LSB；
- 若出现饱和计数 > 0，说明定点格式位宽不够，应优先改格式而不是放宽阈值。

## 失效条件

- 两边元素顺序不同（如 NHWC vs NCHW）—— 会得到极大的误差，先确认布局再比对；
- 参考实现与被测实现的预处理不一致（缩放、均值、padding）—— 误差会整体平移，
  这时「最大误差」没有意义，应比对两边的预处理中间结果；
- 输出是浮点但用了 `--scale` —— 会整体除错，注意 `--scale 1` 时才是原始值。

## 已验证效果

在本作品上用于 HLS C-sim 与板上输出的逐层比对：先确认单层误差在 1 个 LSB 内，
再确认 32 通道中无单通道异常（`--per-channel` 用于发现某一路累加器位宽不足），
最后确认定点权重下的检测框与浮点参考一致。

## 常见误判

| 现象 | 更可能的原因 |
|---|---|
| 误差整体为正或负的常数 | 两边的偏置 / 零点没对齐，不是精度问题 |
| 只有个别通道误差大 | 该通道的累加器位宽或移位量写错 |
| 贴限饱和计数很高 | 定点格式定小了，需要加整数位宽（改 `Q` 的小数位） |
